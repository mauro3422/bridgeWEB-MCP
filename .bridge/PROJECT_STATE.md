# Bridge project state

## Current release
Bridge `0.6.92` is live after controlled HTTP restarts with 149 tools. It extends the native Godot scene boundary for provider 0.3.7: `godot_mcp_instance_list` exposes every connected editor; `godot_scene_open` and `godot_scene_create` accept `projectPath`, `projectId`, or `editorInstanceId`; and mutating scene operations fail closed when multiple editors are connected without an explicit target. End-to-end runtime proof connected Electronics Repair Simulator and GodotAtlas concurrently, then Bridge targeted `D:/Dev/GodotAtlas/`, opened A/B2/B3/B4/C/D, verified D active with `uiAutomation=false`, and left Electronics connected with the same editor instance id. A 2026-08-14 runtime hotfix also removed the wrapper risk-classification drift: `bridge_tool_query` and `bridge_tool_action` now authorize from each tool's final registered annotations instead of independent static dispatch lists. Live proof now accepts `bridge_tool_query -> project_change_consistency` as read-only while rejecting the same target through `bridge_tool_action` and rejecting mutable `project_context_update` through the query wrapper. The hotfix runtime was built from committed HEAD 0.6.92 plus only `src/tool-registry.ts`, so unrelated narrated-media/workflow worktree changes were not activated. Focused tests and the full Bridge regression suite pass. Bridge continues to package MSSR core `0.2.14` and use the existing `godot-scene-authoring` skill; no duplicate skill or workflow guide is needed.
