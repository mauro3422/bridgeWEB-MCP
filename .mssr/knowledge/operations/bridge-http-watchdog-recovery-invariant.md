## HTTP watchdog identity and recovery invariant
Tunnel admin readiness and tunnel process identity are separate checks. For `bridge-local-http`, command-line identity validation must accept the exact profile token whether unquoted, single-quoted, or double-quoted, while rejecting different or prefixed profile names. A healthy tunnel admin endpoint on `127.0.0.1:8081` plus a missing Bridge HTTP listener on `127.0.0.1:3001` is evidence to inspect the HTTP child/watchdog path before blaming or restarting the tunnel. Recovery verification should restart or terminate only the HTTP child when possible and prove that the watchdog recreates it while the tunnel PID remains unchanged. A 502 or client `ECONNRESET` alone does not establish which layer failed, and the original cause of a vanished watchdog process must remain `No resuelta` unless crash evidence exists.

An alive listener that times out on `/healthz`, `/readyz`, `/status`, and `/dashboard` is evidence of event-loop starvation, not by itself a process crash. Dashboard and observability aggregation must run outside the HTTP/MCP event loop, duplicate refreshes must coalesce behind a bounded cache, and dashboard projections must omit unbounded learning arrays while retaining their totals. A cold multi-client dashboard verification must run concurrently with health probes; the runtime boot id and tunnel PID must remain unchanged. The watchdog uses an eight-second probe timeout as additional tolerance for transient host pressure, but isolation—not a larger timeout—is the primary invariant.

The HTTP watchdog's `-DryRun` mode is strictly observational: it must not stop or replace listeners, consume restart requests, or write restart acknowledgements. Regression coverage must use an isolated root and port with an external listener and pending restart request, then verify that all remain intact. A dry-run acknowledgement is not evidence that a restart occurred or that the original process exit was diagnosed.

Watchdog lifecycle evidence is append-only JSONL under `ProjectRoot/logs/bridge-watchdog-lifecycle.jsonl`, with per-event allowlisted component, PID, UTC process start and observation times, uptime-at-observation, known exit code, readiness-failure count, recovery correlation id, trigger/action, requested-stop time, termination confirmation, and replacement PID/start time. Do not record raw command lines, process arguments, stdout/stderr, secrets, prompts, or transcript text. Observation time is not an asserted exact OS exit timestamp. `-DryRun` must not create or append lifecycle records. Rotate a segment at 5 MiB without deleting prior evidence.

Bridge process identity must recognize the actual Node executable token and the expected HTTP entrypoint when Node is installed beneath a path containing spaces or the entrypoint is quoted, while still rejecting unrelated port owners. Keep the identity regression in the isolated watchdog lifecycle test; production listeners must remain untouched by that fixture.
