## HTTP watchdog identity and recovery invariant
Tunnel admin readiness and process identity are separate. For `bridge-local-http`, accept the exact profile token bare or single-/double-quoted; reject other or prefixed names. A healthy admin endpoint at `127.0.0.1:8081` with no Bridge listener at `127.0.0.1:3001` calls for inspecting the HTTP child/watchdog before blaming or restarting the tunnel. Verify recovery by restarting or terminating only HTTP, confirming watchdog recreation and an unchanged tunnel PID. A 502 or `ECONNRESET` does not identify the failed layer; keep a vanished watchdog's cause `No resuelta` unless crash evidence exists.

An alive listener timing out on `/healthz`, `/readyz`, `/status`, and `/dashboard` indicates event-loop starvation, not necessarily a crash. Keep dashboard/observability aggregation off the HTTP/MCP event loop, coalesce duplicate refreshes behind a bounded cache, and omit unbounded learning arrays while preserving totals. Test a cold multi-client dashboard concurrently with health probes; the boot id and tunnel PID must stay unchanged. Use an eight-second probe timeout, but prioritize isolation.

Watchdog `-DryRun` is strictly observational: never stop or replace listeners, consume a restart request, write an acknowledgement, or create lifecycle records. Test on an isolated root/port with an external listener and pending request; verify all remain intact. A dry-run acknowledgement proves neither restart nor diagnosis.

Append allowlisted lifecycle events to `ProjectRoot/logs/bridge-watchdog-lifecycle.jsonl`: component/PID, UTC process start and observation times, uptime, known exit code, readiness-failure count, recovery id, trigger/action, requested-stop time, termination confirmation, and replacement PID/start time. Never store raw command lines/arguments, stdout/stderr, secrets, prompts, or transcripts. Observation time is not an exact OS exit time. Rotate at 5 MiB without deleting prior evidence.

Process identity must match the actual Node executable and expected HTTP entrypoint across paths with spaces and quoted entrypoints, while rejecting unrelated port owners. Keep identity regressions isolated; never touch production listeners.

`BridgeCodeRoot` is the package/source/generated/installed authority for the supervised HTTP child and its self-release audits. The watchdog passes it as `BRIDGE_MCP_CODE_ROOT`; release-consistency and Bridge-owned release claims use that root even though the child working directory remains `ProjectRoot`. Keep logs, runtime state, workspace/project discovery, tunnel files, and restart request/ack files on `ProjectRoot`.
