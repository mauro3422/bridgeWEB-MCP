## HTTP watchdog identity and recovery invariant

For `bridge-local-http`, accept the exact profile token bare or single-/double-quoted; reject other or prefixed names. Treat tunnel-admin readiness separately from process identity. If admin at `127.0.0.1:8081` is healthy but Bridge has no listener at `127.0.0.1:3001`, inspect the HTTP child/watchdog before blaming or restarting the tunnel. Recover by restarting or terminating only HTTP; confirm watchdog recreation and unchanged tunnel PID. A 502 or `ECONNRESET` does not identify the failed layer; without crash evidence, keep a vanished watchdog's cause `No resuelta`.

An alive listener timing out on `/healthz`, `/readyz`, `/status`, or `/dashboard` signals event-loop starvation, not necessarily a crash. Keep dashboard/observability aggregation off the HTTP/MCP loop; coalesce duplicate refreshes behind a bounded cache; omit unbounded learning arrays while preserving totals. Test health probes during a cold multi-client dashboard; boot ID and tunnel PID must stay unchanged. Use an eight-second probe timeout; prioritize isolation.

Watchdog `-DryRun` is observation-only: never stop/replace listeners, consume restart requests, write acknowledgements, or create lifecycle records. On an isolated root/port with an external listener and pending restart request, verify both remain intact. A dry-run acknowledgement proves neither restart nor diagnosis.

Append allowlisted events to `ProjectRoot/logs/bridge-watchdog-lifecycle.jsonl`: component/PID; UTC process start/observation times; uptime; known exit code; readiness-failure count; recovery id; trigger/action; requested-stop time; termination confirmation; replacement PID/start time. Never store raw command lines/arguments, stdout/stderr, secrets, prompts, or transcripts. Observation time is not exact OS exit time. Rotate at 5 MiB without deleting prior evidence.

Match the actual Node executable and expected HTTP entrypoint, including paths with spaces/quotes; reject unrelated port owners. Test identity regressions in isolation; never touch production listeners.

`BridgeCodeRoot` is the package/source/generated/installed authority for the supervised HTTP child's release and self-release audits. Pass it as `BRIDGE_MCP_CODE_ROOT`; release consistency and Bridge-owned release claims use it while the child working directory remains `ProjectRoot`. Pass `ProjectRoot` as `BRIDGE_MCP_PROJECT_ROOT` so data-backed checks and telemetry smokes use the runtime/data owner when verification runs from the code checkout. Keep logs, runtime state, workspace/project discovery, tunnel files, and restart request/ack files under `ProjectRoot`.
