# Bridge privileged Windows operation boundaries

## Privileged Windows operations boundary

Generic shell tools must remain non-elevated and keep their dangerous-command blacklist. When a legitimate local maintenance task needs Windows administrator rights, expose a dedicated tool with a closed semantic profile instead of accepting an arbitrary command or arbitrary target path. The dedicated tool must default to inspection/dry-run when practical, resolve and revalidate its target internally, use a visible UAC elevation boundary, emit an auditable result, and post-verify the observable target state. The first implementation is the `amd-dxc-cache` profile behind `windows_admin_cache_status` / `windows_admin_cache_cleanup`; adding another privileged target requires an explicit new approved profile and regression coverage.

## Privileged Windows storage diagnostics
Privileged Windows disk diagnostics must remain fixed-capability operations, not generic elevated shells. Bridge 0.6.95 adds `windows_admin_storage_audit`, a no-argument read-only UAC tool that reports pagefile allocation, VSS shadow storage, Reserved Storage/storage-reserve quotas, Windows RE placement, and bounded protected-directory summaries. During the 2026-08-15 C: audit, VSS used 0 bytes with no shadows, Windows RE was located on the separate recovery partition, and `fsutil storagereserve query C:` reported 6,711 MB of guaranteed reserve across active reserve IDs. Generic `run_command` privilege restrictions remain unchanged.

## Privileged Windows cache cleanup profiles
Protected Windows cleanup remains a closed, profile-scoped capability rather than generic elevated shell access. `windows_admin_cache_cleanup` accepts only approved enum profiles. As of Bridge 0.6.96: `windows-update-download` targets only `%WINDIR%\SoftwareDistribution\Download`, records `wuauserv`/`BITS` state, stops them only when needed, and restores the prior running state; `edgecore-stale` targets only `%ProgramFiles(x86)%\Microsoft\EdgeCore`, derives the installed Edge version from `msedge.exe`, preserves that version plus non-version directories such as `Optimized`, and removes only older numeric EdgeCore directories. Edge WebView2 is deliberately outside this cleanup boundary because multiple WebView2 versions can be concurrently active for Windows Widgets, WhatsApp, or other applications. Always inspect active process executable paths before pruning versioned runtimes. Cache-status scans are recursive and skip symbolic links; physical free-space delta remains the authoritative reclaim measurement when hardlinks/reused files make logical byte totals misleading.
