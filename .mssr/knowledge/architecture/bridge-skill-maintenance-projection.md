# Bridge cross-project skill-maintenance projection

Bridge preserves portable MSSR skill-selection feedback without becoming a second routing authority. For a `skipped/redundant` decision, `relatedSkillName` is transported exactly as bounded evidence about the peer the host observed covering the same need; that observation is not proof that the two skills are equivalent. Repeated `redundant` and `irrelevant-domain` evidence may be projected into the workspace-level `.mssr/runtime/skill-maintenance-candidates.json`, but that file is generated/reconstructable review data only: `authorityInfluence=false`, `routingInfluence=false`, `canonicalRewriteAllowed=false`, and `autoApplyAllowed=false`. Historical redundancy that lacks an explicit peer may suggest bounded co-occurrence hypotheses only. Any real relation (`requires`, `complements`, `excludes`) or semantic/gate change, merge, split, supersede, or removal remains an owner-reviewed mutation in the canonical skill/router source.

Automatic maintenance-index refresh is a host liveness boundary as well as a semantic one. Bridge waits for the relevant skill-decision event to receive a durable observability persistence ACK before scheduling the projection, debounces repeated evidence, and runs the expensive historical aggregation in a worker thread rather than the HTTP/MCP event loop. Worker completion/failure is observable through `mssr_skill_maintenance_index`; failure leaves durable source telemetry intact and must not fabricate or activate a relation.
