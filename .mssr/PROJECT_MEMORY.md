# Bridge project memory

Optional durable project memories are reference-backed under `.mssr/knowledge/` and indexed by `.mssr/project-context.json`. Keep this root compact: record brief pointers for cross-cutting decisions here and keep technical detail in its indexed owner. Repository-wide reconciliation and continuity handoffs are recorded in `PROJECT_STATE.md` plus bounded docs rather than duplicated here; MSSR selects the relevant modules by stage and structured intent.

## Durable decisions

- **Trace identity:** an explicitly supplied unknown `traceId` has no existing state and cannot borrow another task's `localTraceId` or closure timer. The exact invariant and regression are in [trace integrity and lifecycle](knowledge/observability/trace-integrity-and-lifecycle.md). This prevents explicit task IDs from being rebound to unrelated session work.
- **Jev confidence:** provider scores remain uncalibrated selection evidence, not probabilities or a pass threshold; no automatic confidence cutoff or proposal application follows from the current exploratory runs. When TypeSafe returns a Choice distribution, Bridge 0.6.156 preserves its exact offered option IDs and values in the per-call Librarian evidence; missing maps stay null. This makes future calibration possible but does not itself calibrate the scores. Benchmark evidence, blind-review limits, and calibration gates are recorded in [MSSR Librarian/Jev](../docs/MSSR_LIBRARIAN_JEV.md).
- **Project-context split planning:** Bridge exposes MSSR's Jev planner as an advisory operation that stores a reviewable plan and semantic evidence in user-local state. It does not edit canonical project Markdown or apply the plan; any future apply path requires a separately reviewed and verified change. The tool and boundary are documented in [0.6.164](../../changelogs/0.6.164.md).
- **MSSR/dashboard reads:** isolate retained MSSR/tool-call aggregates in a read-only child and keep snapshot construction in a separate child. Serve a persisted snapshot without waiting for storage bootstrap; refresh on demand. Wait for IPC readiness, distinguish queue acceptance from execution time, and expose bounded worker state for diagnosis. Preserve parent runtime identity/persistence fields and test real-sized data while sampling `/readyz`. Serialize context-inventory cache replacements with unique temporary files. Details are in [dashboard and observability liveness](knowledge/operations/bridge-dashboard-routing-liveness.md) and [0.6.165](../../changelogs/0.6.165.md).
- **MCP binary resource scope:** a stateless unauthenticated request cannot safely own a deferred resource handle across later requests. Keep legacy handles inside the stateful server session and return embedded bytes on modern stateless requests until a trusted stable principal is available; details are in [MCP binary and image transport](../docs/MCP_BINARY_AND_IMAGE_TRANSPORT.md).
- **HTTP code/data roots:** when supervision separates `BridgeCodeRoot` from `ProjectRoot`, package/source/generated/installed release checks follow the code root while runtime storage, project discovery and relative files remain owned by ProjectRoot. The watchdog exports `BRIDGE_MCP_CODE_ROOT`; see the indexed watchdog invariant.
- **Jev provider transport:** the managed Windows HTTP child uses `NODE_USE_SYSTEM_CA=1` to include OS trust roots without disabling TLS verification; keep this process-scoped and classify provider errors without exposing raw messages, response bodies, causes, or credentials.
- **Librarian evidence packs:** `mssr_librarian_evidence_pack` is a deterministic, source-revalidated operation over explicit handles; its `paragraphs` contain verbatim source excerpts and preserve citation provenance. The composed host workflow can retrieve and select evidence, exact-fetch it, ask Jev to review typed relations/contradictions, prepare a reversible synthesis preview, then compose answer paragraphs with citations and independently verify their claims. Jev does not retrieve beyond supplied candidates or generate the prose. See the [Bibliotecario/Jev host workflow](../.bridge/workflow-guides/mssr-librarian-jev-composition/GUIDE.md) and [MSSR Librarian/Jev](../docs/MSSR_LIBRARIAN_JEV.md).
- **Live watchdog code-root adoption:** changing the Windows Startup entry selects code for a future watchdog launch; an already-running watchdog retains the BridgeCodeRoot it received at startup. Declare live adoption only after the active HTTP PID command line and `/status` both identify the candidate. Keep ProjectRoot stable for runtime data; if a controlled process handoff is unavailable, preserve the prior startup bytes and report activation as pending rather than stopping unverified processes.
