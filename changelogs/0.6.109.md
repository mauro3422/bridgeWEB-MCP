# 0.6.109 — 2026-08-19

- Summary: Harden Bridge MSSR trace owner integrity so implicit recovery cannot migrate an open trace across different known project/workflow owners merely because caller/session continuity matches. Same-owner session rotation remains recoverable and auxiliary repositories inside one workflow remain `related_project` evidence instead of replacing the primary owner.
- Areas: mssr-observability, trace-lifecycle, project-attribution, workflow-attribution, sqlite-recovery, bridge-adapter, testing, project-knowledge

- PROJECT_MEMORY: updated

## Changes

- Extended Bridge `MssrTraceHostContext` with `workflowKey` and centralized known project/workflow compatibility for implicit trace recovery.
- Local active-trace reuse now enforces owner compatibility when no explicit `traceId` was supplied.
- Shared-memory candidate selection no longer lets a single same-session candidate bypass known project/workflow ownership.
- Persisted SQLite recovery now filters known project and workflow even when `sessionKey` is available; session identity is continuity evidence, not owner authority.
- `bridge-server` propagates workflow ownership through trace preparation/metric resolution and treats an explicit workflow change as a boundary for the next independent project route.
- Explicit `traceId` remains a deliberate reference to a concrete trace; it does not silently mutate the trace owner.
- Existing supporting-repository behavior is preserved: work in another cwd/repo within the active workflow keeps the primary owner and records the auxiliary repository as `related_project`.
- Strengthened `scripts/test-mssr-trace-contract.mjs` with same-owner session rotation, cross-project rejection, cross-workflow rejection, persisted recovery owner checks and an end-to-end A→B project/workflow isolation fixture.
- Added `.mssr/knowledge/observability/trace-owner-integrity.md` and indexed it as selective memory `bridge-trace-owner-integrity`, avoiding further growth of the already WATCH-level monolithic `PROJECT_MEMORY.md`.
- Recorded the observed contamination defect and proven cause in `docs/INCIDENTS.md`.
- Bridge source version moves to `0.6.109`; packaged `@mauroprime/mssr` remains `0.2.34`. No MCP tool is added.
