## Changes

- Upgraded packaged `@mauroprime/mssr` to `0.2.22` (vendor tarball SHA-256 `656ce2985a512661eb32e050d93e3d2ddb4887f57c0c79221b47e5dfe21c7305`).
- Added `src/mssr-routing-compliance.ts`, a Bridge adapter over portable `evaluateMssrRoutingComplianceOperationalAttention` plus the shared notice transition evaluator. Bridge owns only host observation, action rendering and `bridgeNotices` delivery.
- Migrated ordinary/substantial unrouted tool evidence away from the old producer-specific timer policy. Ordinary unrouted evidence is quiet WATCH; destructive/material work without a route is REVIEW and recommends `skill_bootstrap` rather than blocking the original tool call.
- Migrated trace missing/ambiguous/mismatch, orphan skill load, required-skill-at-boundary, active-trace replacement before outcome, and outcome-without-route producers onto the same portable projection. Existing producer-facing codes are preserved where useful, but portable MSSR now owns severity, semantic fingerprinting, stable-state suppression and resolution.
- Trace mismatch and outcome-without-route can surface as ERROR where attribution or closure safety is at risk; missing/ambiguous attribution and required-skill misses remain REVIEW-level recovery conditions.
- Required-skill remediation is exact: Bridge may render bounded `skill_load`/`skill_bootstrap` actions for missing required skills. Optional selected-but-not-loaded skills are explicitly not compliance failures.
- Added focused adapter fixtures for quiet WATCH, actionable REVIEW, ERROR attribution/closure cases, exact skill recommendations, optional-skill negatives, stable-state no-spam, material fingerprint changes and explicit resolution.
- Preserved existing trace lifecycle blockers/closure gates as separate contracts; C2b notices remain advisory and never authorize or auto-run recovery.
- Existing Context Plane freshness and `project_change_consistency` already detect parts of project-memory/version drift. Explicit unification into one version/project-knowledge mismatch projection is deferred to C2c rather than being conflated with routing compliance.
