# 0.6.175 — 2026-10-12

- Summary: Prevent trace-scoped Bridge notices from leaking into untraced or unrelated chat calls while preserving exact-trace, comparable project/workflow, and truly global delivery.
- Areas: operational notices, trace isolation, chat delivery, Bridge release verification
- PROJECT_CONTEXT: updated
- PROJECT_MEMORY: reviewed-none
- PROJECT_STATE: updated

## Changes

- When a notice carries a trace ID but the active MCP call has no comparable trace, project, or workflow scope, Bridge now keeps the notice count-only as `other` instead of promoting its warning/error body to global attention.
- Exact active-trace matching, comparable project/workflow delivery, and truly unscoped global warnings/errors retain their existing behavior.
- Global `bridge_notice_history` remains available for explicit recovery; this change does not delete or drain historical notices.
- Updated the operational notice contract and indexed project knowledge.
