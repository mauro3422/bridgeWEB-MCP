## Changes

- Added read-only `bridge_notice_history`; runtime tool count increases from 163 to 164. It can filter the bounded recent notice ledger by severity, source, code, timestamp, and delivery state without re-delivering old notices.
- `bridge_notice_status` is now deliberately quiet: it reports pending/history counts and the next inspection action instead of repeatedly injecting notice bodies that were already seen.
- Bridge notices record delivery count/time/mode. Pending + recent history are persisted for up to 24 hours in a bounded ignored `data/bridge-notices.json` snapshot. Writes are debounced and atomic outside the synchronous request path; corrupt, missing, expired, or oversized state is ignored safely at startup.
- Ordinary `project_context_load` now fingerprints advisory WATCH findings per project. A new/changed WATCH is shown once; an identical later load suppresses repeated findings while preserving level/count metadata. Explicit `project_context_health` remains unsuppressed and authoritative for inspection. REVIEW is never hidden.
- `bridge-dashboard-routing-liveness` now uses reviewed MSSR semantic segmentation: dashboard/liveness is the baseline while routing/catalog latency and observability/WAL durability are optional sections. This removes its prior selected-payload pressure without raising `maxChars` or changing durable meaning.
- Bridge vendors and installs the exact verified MSSR 0.2.64 tarball (709650 bytes; SHA-256 `61821a47000b33e64c935a0b4a9a632a4832a62fcbdc03f678aaeee0410e4dcc`). MSSR 0.2.64 reconciles stale old-path Context Message owners only when exact repository evidence proves identity; basename/path similarity alone never aliases repositories.

## Verification

- Focused TypeScript check/build, v060 registry/notices regression, Project Context module regression, Operational Notice regression, and Context Plane regression: PASS.
- The notice regression uses two fresh Node processes against the same bounded snapshot: the first delivers a notice and flushes state, and the second recovers it as delivered history with no pending re-delivery.
- Generated `TOOLS.md` is current with 164 registry tools.
- Full isolated `npm run test:regressions`: PASS on the final release tree. Its integrated liveness probe completed 64/64 persisted writes with 313 concurrent readiness samples, p95 1.43 ms, max 48.99 ms, zero event-loop stalls, and one passive WAL checkpoint. After durable publication, the watchdog adopted live 0.6.130 successfully; `smoke:http` passed with 164 tools and MSSR 0.2.64. Additional isolated liveness stress passed at 8 agents (p95 2.23 ms, max 68.62 ms) and 12 agents (p95 3.04 ms, max 79.05 ms), zero stalls and 64/64 persisted writes in both cases. These stress runs relaxed cold-start/per-tool completion timeouts only; a default 15 s synthetic call timed out at 8 agents, so they are liveness evidence rather than a per-tool SLA.
