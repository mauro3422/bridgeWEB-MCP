## Changes

- Vendored and installed verified `@mauroprime/mssr` `0.2.34` from `mauroprime-mssr-0.2.34.tgz` (`498079` bytes, SHA-256 `f86dd2fd66bf6441d93b61c0dca65e5fe070e3d76ab15de197abbfbb552a2cec`).
- Added `src/architecture-impact-observer.ts` as an internal host adapter, not an MCP tool.
- The adapter loads the canonical C2f-A manifest with portable MSSR, observes the exact C2f-B plan, then delegates ordering/validation back to `observeArchitectureImpactManifest(...)`.
- Existing regular files are hashed byte-for-byte as `sha256:<64hex>` revisions.
- Positive `ENOENT`/`ENOTDIR` absence is reported as `missing`; other expected filesystem inspection failures become explicit `unavailable` with bounded reason codes such as `fs-eacces`.
- Canonicalized real paths must remain inside the canonical project root. A junction/symlink escape is represented as bounded `unavailable/path-outside-project`; it is never read as project evidence.
- Each declared ref is inspected once in manifest order. Bridge adds no hidden retry, baseline lookup, source-set fingerprint, changed/stable comparison, `possible-impact` classification, context request, Operational Notice, watcher/scheduler, queue/history, or persistence store in C2f-B.
- Added `scripts/test-architecture-impact-observer.mjs` covering available/missing/unavailable states, exact SHA-256 values, no retry, path confinement, missing manifest behavior and explicit absence of C2f-C/notice fields.
- Added the focused `test:architecture-impact-observer` script and included it in the aggregate regression chain.
- Updated `.mssr/PROJECT_CONTEXT.md` with only a compact portable-MSSR vs Bridge-host ownership statement and moved the detailed C2f-B boundary to the selective `.mssr/knowledge/architecture/architecture-impact-observer.md` module, indexed as `bridge-architecture-impact-host-boundary` in `.mssr/project-context.json`.
- The first verify-stage bootstrap exposed real Context Plane pressure because the expanded core exceeded its 5000-byte source cap. The detail was modularized instead of raising the cap; subsequent project-context load is valid at 2 core / 9 modules and verify-stage selection recovers the dedicated C2f-B module. The only remaining Project Context Health finding is the pre-existing WATCH for growing `PROJECT_MEMORY.md`.
- `PROJECT_MEMORY.md` was reviewed but intentionally not expanded because this release changes architecture ownership already represented in project context rather than introducing a separate durable operational lesson.
- Bridge source version moves to `0.6.108`. No MCP tool is added; expected live catalog remains `156`.
