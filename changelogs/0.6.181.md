## Goal and root cause
ChatGPT's Bridge connector reported 212 tools but did not advertise the independently implemented `blender_viewport_capture` and `blender_session_snapshot`. Inspection proved that Bridge uses an explicit, separately maintained tool registry: the standalone `D:\Dev\blender-mcp` tool implementation is not automatically published by the active Bridge. Refreshing ChatGPT alone could not add these tools.

## Changes
- Explicit integration module: `src/tools/blender-standalone-proxy-tools.ts`. Publishes only the two vetted tools; delegates their execution to the built standalone `blender-mcp` handlers, preserving the Python implementation and identity checks. `MAURO_BLENDER_MCP_ROOT` can override its standalone repository root (defaults to `D:/Dev/blender-mcp`). Standalone add-on uses TCP 9878, distinct from legacy 9877.
- Registers both tools in `src/tool-registry.ts`; classifies them as side-effectful because they write PNG/.blend output files. Enforces Bridge authorized write path checks and extensions. Snapshot cannot target the live source file. No automatic generic proxy to arbitrary standalone tools was added.
- Regenerated `TOOLS.md` from the registry and kept the old foreground screenshot tool as a separate legacy fallback.
- Contract and protocol regressions: `scripts/test-blender-standalone-proxy.mjs`, `scripts/test-mcp-dual-era.mjs`. They check name/schema parity, fail-closed path rejection, no duplicate tool registration, side-effect classification, HTTP modern+legacy `tools/list` advertisement.
