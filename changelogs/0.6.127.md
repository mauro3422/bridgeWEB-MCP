## Changes

- Bridge now reconciles process-shared trace lifecycle state with `readPersistedMssrTraceState()` before lifecycle-sensitive explicit-trace calls: route planning/bootstrap, `skill_load`, and `mssr_trace_record`.
- Persisted state is adopted only when its lifecycle generation is strictly fresher by lifecycle revision, route count, close revision, maintenance revision, or terminal closed state.
- Older persisted state never overwrites a newer in-memory continuation. Loaded skills and completed phases are merged monotonically while trace owner identity remains governed by the existing owner-integrity contract.
- Ordinary trace-aware tools do not pay this reconciliation read on every call; the durable lookup stays on lifecycle boundaries.
- Regression coverage now protects both directions: a fresher persisted maintenance close must unblock a stale-RAM outcome, while a newer RAM continuation must remain blocked rather than being rewound by older persistence.
- Added selector-backed durable knowledge at `.mssr/knowledge/observability/trace-lifecycle-reconciliation.md` rather than expanding the already-growing root `PROJECT_MEMORY.md`.
- Fixed release-document drift where root `CHANGELOG.md` still pointed at 0.6.125 after 0.6.126 had already become live/current.
- Compact `skill_bootstrap` now treats host-only `bridgeTiming` diagnostics as best-effort: keep full timing when it fits, fall back to compact timing, then omit timing before rejecting an otherwise valid bounded response.
- The fallback is implemented through the shared exact-envelope helper `withBestEffortOptionalResponseField`, so optional diagnostics cannot silently raise the compact response above `maxEnvelopeChars`.

## Incident evidence

- The portable/persisted lifecycle evidence reconstructed the affected trace as `canCloseSuccess=true`, but the live Bridge host rejected the same success outcome with `mssr-success-outcome-blocked-stale-close`.
- The host coordinator selected `sharedTraces.get(explicitTrace)` whenever RAM existed, so `restore(explicitTrace)` never ran and a newer SQLite lifecycle could remain invisible to the gate.
- A red regression reproduced the contradiction before the correction and passed after reconciliation was added.
- A real ChatGPT Web-side investigation reproduced a separate compact-envelope failure in 94 ms: `skill_bootstrap` required 32,759 serialized characters for a 32,000-character envelope only after optional `bridgeTiming` was attached. The same base response was otherwise valid.
- The corrected build returns the same worst-case bootstrap as a bounded 31,728-character partial response instead of throwing; transport health remained independently `live/ready` with zero new tunnel-service 502 / local no-status failures from the active baseline.
