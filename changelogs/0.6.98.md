## Changes

- Packages `@mauroprime/mssr` 0.2.18 from the versioned vendor tarball and consumes portable initialization, health, capture-planning and canonical project-context selection APIs.
- Removes Bridge's active `.bridge` project-context fallback. `project_context_load` now returns explicit uninitialized/invalid evidence instead of loading legacy PROJECT_* documents; portable MSSR owns semantic module eligibility, required overflow, ambiguity and budget selection.
- Adds `project_context_initialize` for one repo or recursively discovered workspace. It creates bounded `.mssr` skeleton/control files, separates `.mssr/knowledge/` from `.mssr/runtime/`, and may remove only the known obsolete MSSR-owned `.bridge` artifact set. Unrelated Bridge-specific `.bridge` content is preserved.
- Adds read-only `project_context_health`, `project_context_modularization_plan`, and upgrades `project_context_audit` to recursive portable repository discovery plus MSSR Project Context Health (`ok/watch/review`). The planner proposes exact indexed-section moves into `.mssr/knowledge/<topic>/` with hashes/selectors while leaving core narrowing and unindexed knowledge as explicit review decisions.
- Makes `project_context_update` fail closed until `.mssr/project-context.json` is valid; it no longer reads or migrates `.bridge` state implicitly.
- Adds `project_context_capture`: portable MSSR plans a reviewed `.mssr/knowledge/<topic>/<id>.md` module and Bridge performs a hash-checked content+manifest transaction with rollback. Existing targets require an explicit prior-read hash.
- Extends the trace watcher so normal `project_context_load` returns Project Context Health and observed `projectInitialized`/`projectContextHealth` feed portable `evaluateMssrProjectKnowledgeMaintenance`; a REVIEW can therefore make maintenance due without a separate manual health call. Notices expose bounded health evidence but remain advisory and never auto-write project authorities.
- Adds daily workspace Project Context Health snapshots (`data/project-health.json`) using portable MSSR recursive discovery/health. The scheduler checks hourly but captures at most daily, stores metadata only with 90-snapshot retention, exposes `/api/mssr/project-health`, renders a dashboard card, keeps WATCH quiet, and emits a deduplicated REVIEW notice with audit/planner action. It never auto-edits project knowledge.
- Adds `includeCore=false` to the portable MSSR project-context loader and uses it for phase replans, so Bridge never reimplements or double-reserves an already-delivered core.
- Updates tool risk metadata/guidance, AGENTS, README, status/current project authorities and generated-tool source descriptions to the canonical-only contract.
- Hardens MSSR regression isolation: fixtures that create private metrics/log sandboxes now also bind their SQLite and MSSR events JSONL paths locally, preventing prior suite traces/events from leaking into fresh-session continuity or HTTP telemetry tests.
