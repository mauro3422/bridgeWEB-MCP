## Changes

- Added `project_context_maintain` as a dedicated write tool backed directly by packaged MSSR 0.2.63 `maintainMssrProjectContext`.
- The executor moves only exact already-indexed non-core Markdown sections from growing PROJECT_* authorities into `.mssr/knowledge/<topic>/`, preserving module id, kind, selectors and selected bytes with lock/hash/readback/rollback guards.
- Semantic decisions remain protected: core narrowing, whole-file semantic segmentation, overlapping consumers, changed source bytes and already-segmented budget pressure return explicit blockers instead of being rewritten.
- `project_context_health` and `project_context_modularization_plan` remain read-only. Their tool metadata now points agents from pressure -> plan -> safe maintainer, while semantic blockers require explicit review.
- Project-knowledge maintenance notices may expose `project_context_maintain` as an actionable recovery when the active trace has a context target and a known project root. The notice/scheduler never executes it silently.
- New optional memory continues to use `project_context_capture`, so normal writes are reference-backed from creation rather than waiting for later cleanup.
- Runtime tool count increases from 162 to 163.
