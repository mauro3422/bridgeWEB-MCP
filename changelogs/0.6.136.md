## Changes

- Adopt exact `@mauroprime/mssr 0.2.69` from `vendor/mauroprime-mssr-0.2.69.tgz`; the vendored artifact SHA-256 is `b46eacd8025c4195e852b5b52deeca38cb4e482395a0c9396a0695be8d8b14a1`.
- Enforce R1 on the explicit-`traceId` path before `adopt(...)`: Bridge evaluates portable `evaluateMssrTraceOwnerCompatibility(...)`, permits progressive binding only for previously unknown owner dimensions, and blocks known project/workflow mismatches without mutating the existing trace owner.
- Preserve same-owner continuation across restart/persisted recovery while requiring separately owned/delegated traces or bounded related-project evidence for legitimate cross-project work.
- Add bounded `mssrLifecycle` metadata (`effect` + `scale`) to the effective registered tool schema. Control-plane calls are recursion-exempt; trivial reads remain lightweight; substantial inspect/verify/mutate/persist/publish/external-side-effect operations enter managed lifecycle according to MSSR 0.2.69.
- Add the dispatcher R2 preflight before the original handler. When lifecycle is missing or incomplete, Bridge returns `executed:false` with `mssr-lifecycle-preflight-required` and the required MSSR action; the original operation performs no side effect. After the caller processes the routed context/required skills, retrying the operation can execute normally.
- Reuse compatible trace/routes instead of manufacturing lifecycle evidence. C2b routing compliance now observes after this gate and remains fallback/recovery evidence rather than the primary activation mechanism.
- Add dedicated regressions `test-mssr-trace-owner-isolation.mjs` and `test-mssr-lifecycle-host-adoption.mjs`, and update legacy trace-contract fixtures so independent project contexts no longer inherit an unrelated task identity.
- Update the indexed Bridge trace/lifecycle memory with the R1/R2 host invariant; no new queue, watcher, semantic authority, prompt classifier, or LLM eligibility classifier is introduced.
