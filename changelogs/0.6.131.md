## Changes

- Project Situation still applies receipt TTL/retention rules, but before evaluating current consistency it now projects each active delivery receipt down to sources whose exact `canonicalOwner + ref` identity is present in the current authoritative project observations.
- Historical receipts remain unchanged in `.mssr/runtime/context-inbox.json`; the watcher does not acknowledge, rewrite, expire, or delete them. Portable MSSR receipt/situation semantics are unchanged.
- A retained receipt for a versioned changelog that is no longer one of the repository provider's current canonical candidates no longer creates `canonical-baseline-missing` or counts as active current context merely because its TTL has not expired.
- Current authorities such as `.mssr/PROJECT_MEMORY.md` and `.mssr/PROJECT_STATE.md` remain comparable against their delivered historical revisions. Real stale revision mismatches therefore continue to produce REVIEW and `revalidate-context-evidence`.
- Multi-source receipts are filtered source-by-source; the receipt participates in the current projection when at least one exact source remains canonical.
