## Changes

- Adopts exact packaged MSSR `0.2.50` (`pkg:0.2.50#c992bf9b`) from the verified canonical artifact. The vendored package is byte-identical to the source release (`600243` bytes, SHA-256 `c992bf9b58d116ab8430b00e97a7d86e8d263fd46a2912a616783a3b40ec0ce3`).
- Bridge remains the host observer/sanitizer while portable MSSR owns deterministic repeated-friction clustering and priority. No routing benchmark score or routing decision is changed by this operational maintenance signal.
- Adds bounded failed-call projection for direct tools and delegated logical targets, then reduces local redacted errors to stable signatures such as `schema:timeoutMs:maximum`, `runtime:timeout`, `target:not-found`, or `patch:replacement-conflict` before passing evidence to MSSR.
- Stable schema signatures intentionally discard numeric bounds, so the historical `work_once` 45-second maximum failures and the later 60-second maximum failures remain one semantic maintenance cluster rather than splitting when wording or limits change.
- Child process non-zero exits and unknown free-form errors are deliberately excluded from tool-contract clustering. They remain available in legacy aggregate metrics but do not masquerade as Bridge tool maintenance debt.
- `bridge_tool_audit` now exposes sanitized `maintenanceFriction`, preserves `toolName` on global clusters, returns no raw error text, and makes `needs-attention` prioritize actionable `review`/`error` repeated-friction clusters ahead of isolated low-sample noise. `watch` evidence does not receive that priority boost.
- No MCP tool was added or removed; the runtime catalog remains 156 tools.
- Project-context maintenance narrows the always-loaded architecture core by moving Skill/Project Health and Operational Notice/Situation details into indexed observability modules, and splits Architecture Impact semantic ownership from writer/runtime integration. The durable ownership boundaries remain unchanged; the extracted details are now loaded only when the structured intent selects them.
- Project Memory storage parity moves six already-indexed optional memories out of `.mssr/PROJECT_MEMORY.md` into `.mssr/knowledge/<topic>/` refs without semantic rewrites. Module ids, kind, selectors, priorities and selected payload hashes are preserved; the root shrinks from 16850 to 12719 bytes and portable MSSR 0.2.51 Health moves from WATCH (`growing-authority` + `root-backed-memory-fanout`) to `ok`.
- Adds `scripts/migrate-project-memory-refs.mjs` as a reusable conservative host migration transaction. It is check-only by default; `--apply` additionally requires the exact reviewed candidate ids through `--expect`, aborts on concurrent source changes or destination collisions, writes destinations before manifest/root cleanup, and verifies payload/selector parity plus Health after mutation. It never discovers semantics from arbitrary unindexed prose and never background-migrates repositories.
- The immutable MSSR `0.2.51` artifact (`pkg:0.2.51#37bc9ba7`, 603522 bytes, SHA-256 `37bc9ba7bf889abeb9900335da9f75bf535f416eddd6b4a28fc523434f905218`) is staged under `vendor/` for the next safe adoption window. This source maintenance does **not** claim live adoption: `package.json`, installed `node_modules`, and the current HTTP runtime remain on MSSR 0.2.50 until an authorized restart/readback gate.
