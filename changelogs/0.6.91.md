# 0.6.91 - 2026-08-14

## Contract

- Summary: add dedicated native Godot scene lifecycle tools so ChatGPT can open existing scenes and create/persist scenes in the already-connected editor without Ctrl+O, clicks, SendKeys, or launching another Godot instance. ## Changes

- Adds `godot_scene_open`: accepts 1–24 explicit `res://...tscn|scn` paths, reuses the connected editor, validates each scene with `read_scene`, opens it through `EditorInterface.open_scene_from_path` via provider `open_in_godot`, verifies the active edited scene with `scene_tree_dump`, and optionally leaves a requested scene active.
- Adds `godot_scene_create`: creates a scene through provider `create_scene`, reads the persisted result back, and optionally opens/verifies it in the same editor. It supports an explicit root type/name, nested child specs, and an optional root script.
- Both tools reject absolute/non-scene/escaping paths, require an existing connected editor, and explicitly report `uiAutomation=false`; disconnection is a recovery condition rather than permission to launch another editor or click through the UI.
- Adds focused fake-provider regression coverage for batch scene opening, final active-scene selection, invalid paths, create/readback/open, and persist-only creation.
- Regenerated the Godot tool documentation category to include the two dedicated operations.
- Vendored `@mauroprime/mssr` 0.2.14 so live Bridge routing consumes `godot-scene-authoring` metadata/fixtures instead of the stale 0.2.12 package.
