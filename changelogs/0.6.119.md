## Root cause

- The dashboard issued twelve parallel requests every five seconds.
- Metrics overview and summary each repeated the same full routing-profile scan.
- The MSSR summary returned multi-megabyte learning arrays and could become dramatically slower under SQLite contention.
- Because dashboard, MCP, and health endpoints shared one Node event loop, a refresh delayed readiness beyond the watchdog's three-second timeout. Three aligned misses caused the watchdog to replace an alive HTTP child while the tunnel remained healthy.

## Changes

- Replaces dashboard fanout with one `/api/dashboard/snapshot` request.
- Computes the complete snapshot in a worker so synchronous SQLite and MSSR analysis cannot block MCP or liveness endpoints.
- Coalesces concurrent dashboards and caches completed snapshots for 15 seconds.
- Reuses a single metrics profile scan for overview and summary.
- Bounds the dashboard MSSR projection while preserving aggregate totals; full diagnostic APIs remain available.
- Raises the watchdog probe timeout default from three to eight seconds as defense in depth.
- Adds regression coverage for projection size and the single-request refresh contract.
