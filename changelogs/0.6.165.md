## Changes

- Route `/api/mssr/summary`, `/api/tools/audit`, and the `/api/metrics/overview`, `/summary`, `/recent`, `/errors`, and `/timeline` aggregations through the existing read-only dashboard worker instead of running retained-history SQLite work synchronously in the HTTP process. `/api/metrics/status` remains in the parent so its runtime identity and persistence queue remain authoritative.
- Keep expensive dashboard snapshot construction on its own child, separate from serialized read APIs, so a snapshot refresh cannot hold up summary/audit/metrics reads. Serve a valid persisted snapshot immediately during storage initialization and refresh it on demand; eagerly warm only when no persisted snapshot exists.
- Wait for each child to register its IPC listener before dispatch. Track when a request is accepted by the worker, apply a five-minute queue-acceptance timeout and start the separate 120-second execution timeout only after acceptance. Expose bounded worker health and pending request types in `/status` without request ids.
- Move the audit projection used by `/api/dashboard/snapshot` into that worker as well; preserve endpoint response shapes, validation, defaults, runtime identity and the storage-initialization gate.
- Ensure both worker_threads and child-process IPC dispatch recognize every worker request kind. Serialize concurrent context-inventory cache writes with unique temporary paths and targeted cleanup to avoid Windows rename races.
- Add liveness regressions for 30,000 retained MSSR events and 30,000 tool calls; sample `/readyz` during summary, audit, and five concurrent metrics read APIs.
