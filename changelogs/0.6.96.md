# Bridge 0.6.96 — 2026-08-15

- Summary: extend the closed Windows admin cache-cleanup boundary with two fixed profiles for reclaiming C: space without exposing arbitrary elevated paths or commands.
- Areas: Windows administration, disk cleanup, Windows Update, Microsoft EdgeCore, UAC, filesystem safety.

## Changes

- `windows_admin_cache_cleanup` now accepts `windows-update-download` and `edgecore-stale` in addition to `amd-dxc-cache`.
- `windows-update-download` is pinned to `%WINDIR%\SoftwareDistribution\Download`, stops only `wuauserv`/`BITS` when they were running, deletes only that download cache, and restores the prior running state afterward.
- `edgecore-stale` is pinned to `%ProgramFiles(x86)%\Microsoft\EdgeCore`; it resolves the installed Edge version from `msedge.exe`, preserves that matching version plus non-version directories such as `Optimized`, and removes only older numeric EdgeCore version directories.
- Edge WebView2 application directories are explicitly outside this profile; live process inspection showed multiple WebView2 versions can remain concurrently in use by Windows Widgets and WhatsApp.
- The helper now records recursive before/after byte counts, deleted items, failures, service state, and protected Edge versions in its elevated receipt.
- The non-elevated cache status/dry-run scanner now walks profile trees recursively while skipping symbolic links, so nested caches no longer report misleading zero-byte summaries.
- Regression coverage validates all three allowed profile names and continues to reject arbitrary profile/path input.
