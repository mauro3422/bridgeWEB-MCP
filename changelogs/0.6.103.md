## Changes

- Upgraded packaged `@mauroprime/mssr` to `0.2.23` (vendor tarball SHA-256 `9a97a16b17a908a514b1d9717ffc99f378a8074388bc3f6b278e078ef29681c2`). Critical C2c runtime files are byte-identical between MSSR source dist and Bridge-installed package.
- Added `src/mssr-consistency.ts`, the generic Bridge adapter over portable `evaluateMssrConsistencyOperationalAttention` plus the shared notice transition evaluator. Bridge owns observation/action rendering and `bridgeNotices`; MSSR owns severity, semantic fingerprint, mismatch reason codes and recovery recommendations.
- Added `src/release-consistency.ts`, a metadata-only producer for two semantic claims: `bridge.release-version` (`package.json` canonical vs `src/config.ts`, `dist/config.js`, and live runtime replicas) and `bridge.mssr-package-version` (declared packaged dependency vs installed package). The first successful observation after each Bridge start uses the critical `post-restart` boundary; subsequent scans use ordinary observation.
- Added `/api/mssr/release-consistency` for the latest bounded projection. The scheduler uses the existing `bridgeNotices` transport/history and does not create a second notice database.
- Freshness and present consistency remain separate: historical receipts/memory claims can remain valid evidence of what was believed then while projecting REVIEW when their bounded claim disagrees with current canonical authority. Bridge does not parse or rewrite whole free-form memories.
- C2c recovery actions are advisory only. They may recommend canonical inspection, source/replica comparison, rebuild, installed-package refresh, live-runtime verification, context revalidation or replanning; no notice executes a build/install/restart/write.
- Added `scripts/test-mssr-consistency.mjs` covering healthy parity, stale generated/live runtime, stale installed MSSR, historical receipt mismatch, stable-state suppression, explicit resolution, missing evidence and privacy-safe notice payloads. Added it to the authoritative regression chain.
- Corrected the root `CHANGELOG.md` compatibility pointer, which had remained on 0.6.92 while versioned release history had advanced. This is an example of the stale-claim class C2c is designed to surface when represented as a structured claim.
