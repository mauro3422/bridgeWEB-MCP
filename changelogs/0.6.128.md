## Changes

- `work_once` accepts the wider timeout shape callers may already send, but any request above the 60-second synchronous budget is **not executed**; it returns a deterministic redirect to `work_begin` / `terminal_start` so a tool-schema mismatch cannot hold one MCP call open or accidentally duplicate long work.
- `git_restore_file(staged=false, worktree=false)` is now a reachable recovery no-op. The public schema no longer rejects the request before the handler can explain that no restore target was selected; no repository bytes are changed.
- Added `scripts/bridge-process-diagnostics.ps1`. The external watchdog can collect bounded process evidence independent of the Bridge HTTP event loop: PID/parent, start/uptime, sampled CPU, working/private memory, thread/handle counts and listener ownership. Raw command lines, process output, prompts and secrets are intentionally excluded.
- Before an alive-process readiness recovery, the watchdog captures external process diagnostics first and then attempts `/status` as supplemental evidence. When the managed HTTP child has already exited, the watchdog also preserves its exit code when available before replacement.
- `test-observability-http-liveness` now models six independent modern MCP callers, alternating `project_context_load` and `skill_bootstrap`, while a separate stream probes `/readyz`. It verifies stable PID/boot, no readiness failures and no new event-loop stalls.
- Adopted vendored/installed `@mauroprime/mssr 0.2.63`. Source/vendor tarball SHA-256 parity is verified, and sampled critical installed `dist` files are byte-identical to the canonical MSSR source build.
- Project memory was split out of the monolithic root into selector-backed `.mssr/knowledge/` modules. The root `PROJECT_MEMORY.md` remains only a compact routing pointer; MSSR still owns project-context selection and Bridge remains the host adapter.
- Read-your-writes metric aggregates now use a bounded SQLite read snapshot while reconciling the in-memory persistence overlay. This closes a race where one traced call could briefly appear twice after its row became durable but before the worker acknowledgement removed its overlay entry, or disappear if those reads crossed the commit boundary in the opposite order.

## Incident evidence

- A 2026-09-17 recovery was observed where the managed Bridge HTTP process had actually exited; the watchdog correctly restored HTTP and subsequently recycled the tunnel after its own readiness threshold. Windows Application event logs did not provide a matching Node/Bridge crash record, so the process-exit root cause remains **unresolved**.
- Earlier suspected heavy paths did not reproduce starvation in isolation: the complete Project Situation scan over 29 repositories completed in about 136 ms with roughly 10.6 ms maximum timer gap, and aggressive file exploration remained around 13 ms event-loop gap.
- Concurrent synthetic MCP routing/context work likewise did not reproduce the historical failure. This release therefore improves evidence quality and regression coverage without claiming an unproven root-cause fix.
