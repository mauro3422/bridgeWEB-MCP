## Changes

- Packaged `@mauroprime/mssr` 0.2.26 from final verified tarball SHA-256 `1e2edfd6acc2a10650c7db71ee087b2189031a37fcddf8e8e096ebdc816d81fc`; installed `dist/situation-model.js` is byte-identical to MSSR source dist.
- Added `src/project-situation.ts`: a managed-project metadata-only watcher over durable Context Plane delivery receipts versus current canonical repository revisions. Projects without active receipts skip the heavier repository collection pass.
- Situation snapshots persist under ignored `data/project-situation.json` by default so stable REVIEW is suppressed across Bridge restarts. The store records levels/fingerprints/categories/reason codes/refs and excludes raw PROJECT_MEMORY/doc bodies, prompts, transcripts and private reasoning.
- C2e classification adds notice class/category/bounded priority while retaining the existing `OK/WATCH/REVIEW/ERROR` Operational Notice levels and the single `bridgeNotices` queue/history/TTL/automatic-drain path.
- C2d remains recommendation owner. Bridge renders only `ready` actions; for stale project-knowledge evidence, `revalidate-context-evidence` may point to `project_context_load({ projectRoot })`. No watcher action autoexecutes.
- MSSR 0.2.26 closes receipt truthfulness: re-selecting an existing Context Message refreshes durable `sources`, `traceId`, and `nextGate`; newest/current evidence supersedes older receipts, allowing a stale-context notice to resolve and remain resolved.
- Added `GET /api/mssr/project-situation` and lifecycle scheduler integration. Shutdown stops the scheduler explicitly.
- All HTTP test fixtures and the isolated regression runner now isolate Project Situation state in addition to Skill/Project/Runtime Health stores, preventing test-generated evidence from polluting live observability.
- Added `scripts/test-project-situation.mjs` with stale→REVIEW, stable silence, refresh→RESOLVED, expired receipt, cross-restart suppression and raw-content non-persistence coverage.
- Hardened the Skill Health and Project Health HTTP fixtures after one long-suite `ECONNREFUSED`: endpoint checks now use bounded readiness polling and distinguish temporary refusal from an exited `dist/http.js` child with captured exit/output evidence. This changes test diagnostics only, not production HTTP behavior. A separate lost connector response during isolated Project Health was correlated through Bridge metrics to a successful exit-code-0 operation rather than blindly retried.
