## Changes

- Vendored verified MSSR `0.2.32` (`484602` bytes, SHA-256 `f99b7cd6bf2dfa22308f8d6c9f961ca2cf164d55e2dab60631fec9f35d048fc7`) and moved the Bridge package dependency from MSSR 0.2.31 to 0.2.32.
- Added `scripts/test-operational-notice-e5-invariants.mjs` as the final integration matrix. It proves that E4 direct-host delivery remains independent after Bridge adoption, while Bridge continues to use only its existing `bridgeNotices` queue.
- Repeated delivery of the same MSSR semantic event coalesces under the stable portable dedupe key, increments only the host occurrence counter, and preserves the exact `MssrNotice.noticeId` and serialized semantic payload.
- Bridge-native notices remain plain `BridgeNotice` values without synthetic `mssrNotice` semantics.
- Generic external-MCP notices may use the same ordinary Bridge transport while retaining external source/code/details and without false MSSR normalization.
- The strict portable schema continues to reject queue ids, TTL, attempts, delivery timestamps, actions, tool names and execution fields; both notice and semantic details remain advisory-only.
- Bridge host `actions` remain inert delivery metadata returned by queue/drain. They are not inserted into `MssrNotice` and are not executed by notice enqueue/drain.
- Installed MSSR 0.2.32 exposes the E4 `deliverMssrNoticeV1` helper, proving direct-host delivery is available without making Bridge switch to that transport.
- Bridge version moves to 0.6.107. No MCP tool is added; expected live catalog remains 156 tools.
