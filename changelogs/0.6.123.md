## Changes

- `work_begin` / `terminal_start` remain the single authoritative generic background-work mechanism: they return a session id immediately and multiple sessions may run concurrently.
- Terminal sessions retain optional `traceId` correlation and expose it through read/list snapshots.
- Start/completion events emit bounded Bridge Notices with `work_peek` recovery actions. Notices deliberately omit the command and stdout/stderr; the terminal manager remains the source of truth.
- `work_once` stays synchronous and bounded to 60 seconds. Long work is not reimplemented as a second generic job scheduler.
- Adds a regression that starts two concurrent background sessions, verifies distinct ids/trace visibility, reads both completions, and checks privacy-safe lifecycle notices.
- Adopts exact vendored `@mauroprime/mssr` 0.2.61 artifact (`mauroprime-mssr-0.2.61.tgz`, SHA-256 `9bc3a9f3ceeaa4cb204d0f52e104a98a038a1240ec56aeef4effdc4e8ada27e0`). MSSR 0.2.61 routing audit covers `drawing-tutorial-sheet` with explicit metadata plus positive/continuation/nearby-negative fixtures.
