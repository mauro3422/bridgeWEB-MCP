# 0.6.174 — 2026-10-12

## MSSR emergency recovery from stale connector catalogs

- Fixed a lifecycle deadlock when an indexed MSSR core exceeds its declared budget while ChatGPT's connector catalog omits the newer dedicated `project_context_recover_core` schema.
- The exact, explicitly confirmed `bridge_tool_action` delegation to `project_context_recover_core` now reaches the **same** fail-closed handler without requiring the already-blocked `skill_bootstrap`.
- No arbitrary delegated write, shell command, ordinary `project_context_update`, wrong tool confirmation or mutation outside an oversized indexed core gains a lifecycle bypass.
- The error response now tells the client how to discover the runtime schema with `bridge_tool_schema` and invoke the exact emergency fallback when its dedicated schema is not advertised.
- All core repairs still require a valid project-context manifest, the exact core heading, original SHA-256 and a reviewed replacement smaller than the allowed core budget; the writer rejects attempts to grow a known core over budget.

## Validation

- TypeScript `npm run check` and `npm run build`.
- `scripts/test-project-context-core-recovery.mjs`: reproduces the over-budget bootstrap failure, proves ordinary/delegated writes remain blocked, directly repairs exact core, repairs via confirmed fallback despite absent connector schema, rejects SHA/heading/budget mismatches and protects the manifest.
- `scripts/test-mssr-lifecycle-host-adoption.mjs`: lifecycle isolation.
- The incident was observed on Elemental Frontier: its `.mssr/PROJECT_CONTEXT.md` temporarily reached 2,004 bytes against the 1,800-byte core contract. A user-reviewed reduction restored the project to 1,195 bytes; `project_context_health` then reported OK.

## Rollout

- Running baseline before controlled activation: Bridge 0.6.173 with HTTP and tunnel `/readyz` both 200; source branch `codex/bridge-0.6.173-activation-readback`.
- Activate only after full tests, keep the previous version available, verify HTTP/tunnel readiness and both MCP eras.
- This is an emergency accessibility change, not a relaxation of normal MSSR lifecycle or privacy protections.
