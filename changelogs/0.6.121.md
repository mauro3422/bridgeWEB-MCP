# 0.6.121 — 2026-09-15/16

## Summary

Close two latency spikes observed after the first 0.6.120 live adoption without changing MSSR routing semantics: WAL maintenance now waits for a real quiet period, and the Codex skill catalog is invalidated by filesystem watchers instead of forcing a full rescan every 30 seconds when watcher coverage is healthy.

## Changes

- `src/metrics-wal-maintenance.ts`
  - turns the checkpoint scheduler from throttle-from-first-write into debounce-from-last-write;
  - each new receipt resets the idle timer;
  - writes arriving during an in-flight checkpoint schedule the next passive checkpoint only after the worker completes and the next quiet period begins.
- `src/tools/skill-catalog-tools.ts`
  - treats native `fs.watch` coverage as the primary Codex catalog invalidation authority;
  - uses the bounded TTL only for roots whose watcher is missing or has failed;
  - retries watcher installation on later calls after fallback/error states;
  - exposes scan/hit/invalidation diagnostics through full `skill_catalog` source health while compact route/bootstrap payloads omit those diagnostics so context budget is preserved.
- `scripts/test-metrics-wal-maintenance.mjs`
  - proves consecutive writes keep the checkpoint deferred and that one checkpoint runs after the quiet period.
- `scripts/test-routing-latency.mjs`
  - verifies warm catalog reuse and watcher-first behavior across the old TTL boundary without requiring a rescan when no watcher invalidation occurred.
