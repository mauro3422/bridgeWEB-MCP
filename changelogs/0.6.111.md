## Changes

- Adopt exact packaged MSSR 0.2.47 from `vendor/mauroprime-mssr-0.2.47.tgz`; source, lock and installed dependency use the same versioned artifact. Integrity hashes remain receipt/readback evidence and are not duplicated manually into project prose.
- Add `src/architecture-impact-host-adapter.ts` as the Bridge I/O adapter around portable `planArchitectureHostAdoption` / `evaluateArchitectureHostAdoption`. MSSR retains reverse-map, projection/refinement, derived/invariant, reviewed-current and context-feedback semantics.
- The central Bridge tool dispatch prepares Architecture Impact only after normal routing/lifecycle guards allow execution, then evaluates only after the mutation succeeds. A host-observation failure is advisory and fails open to REVIEW rather than changing tool authorization.
- ChatGPT Web live proof exposed a host continuity defect hidden by same-instance tests: a new MSSR route cleared the session workflow even when that route supplied an explicit `workflowKey`, so a writer arriving through a rotated HTTP/MCP instance could lose its scoped project root and skip Architecture Impact. Bridge now retains the explicit/current session workflow and resolves writer roots across MCP instance rotation without moving semantic ownership out of MSSR.
- Initial runtime coverage is deliberately bounded to explicit-path writers: `write_text_file`, `apply_patch`, `edit_lines`, `binary_file_write` and `git_restore_file`, including delegated dispatch. Arbitrary shell mutations are not claimed as covered without a trustworthy changed-file receipt/diff boundary.
- Optional TypeScript symbol evidence uses MSSR's reference analyzer over Bridge-read source text/revisions. Derived/invariant graph evidence reuses the existing Bridge import graph; derived edges remain candidate-only and only repository-declared invariants can raise invariant attention.
- Add minimal Bridge self-host Architecture Impact, structure and invariant declarations for the adapter boundary. The invariant forbids the host adapter from depending on Bridge `project-context-tools` semantics instead of the portable MSSR contract.
- Host-local baselines/reviewed-current receipts live only under ignored `.mssr/runtime/architecture-impact/`. Baseline creation requires explicit `--reviewed`; no baseline, receipt, ADR or canonical relationship is auto-created or auto-updated.
- WATCH remains quiet. REVIEW is mapped to the existing Bridge notice transport with bounded architecture ids, reason codes and exact context/authority requests; raw hashes and source payloads are not injected into agent context.
