## Changes

- Upgraded packaged `@mauroprime/mssr` to `0.2.21`.
- Added `src/runtime-health.ts` with metadata-only snapshots under ignored `data/runtime-health.json`, bounded to 96 observations and explicitly excluding prompts, request payloads and restart reasons.
- Runtime health correlates tunnel health (`healthz`/`readyz`), persisted boot continuity, and watchdog restart metadata; Bridge does not invent client-side 502 observation when the response was lost outside the process.
- Added `/api/mssr/runtime-health` and a dashboard card for tunnel/runtime/restart state.
- A new runtime boot with otherwise healthy infrastructure is informational WATCH; pending restart or degraded tunnel is REVIEW; unavailable tunnel/runtime or failed restart is ERROR. Resolution uses the same MSSR transition contract.
- Migrated Roblox system awareness to portable provider/target projection. Provider availability and target continuity are distinct: inactive/warming stays quiet WATCH, missing/ambiguous/inspection-failed target is REVIEW, unavailable provider is ERROR.
- Removed producer-specific Roblox state-change/dedupe semantics in favor of the common Operational Notice Plane transition evaluator and existing `bridgeNotices` transport.
- Added focused regressions for runtime-health persistence/privacy, boot continuity, pending restart, tunnel degradation/failure/recovery, HTTP/dashboard projection, and Roblox provider/target mapping.
- Added a release-integrity invariant: npm `file:` dependencies can retain stale installed bytes when a same-version tarball is replaced, so adoption must verify source/vendor/installed SHA-256 parity instead of trusting `npm install` output.
- Live post-adoption readback exposed that temporary HTTP test processes could write boot snapshots into the production `data/runtime-health.json`. Hardened `run-isolated-npm-test.mjs`, standalone HTTP fixtures and the PowerShell HTTP regression so Skill Health, Project Context Health and Runtime Health all use temporary stores/roots during tests.
- Removed 9 known test-generated runtime snapshots only after a precondition verified the production boot/PID/ack identity; preserved all legitimate snapshots for the live boot. Focused post-fix verification proved subsequent tests do not alter live health-store identity.
- Gate C2b remains separate: routing-compliance / required-skill anomaly producers are the next migration, followed by selected reusable project watchers.
