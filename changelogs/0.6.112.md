## Changes

- `workspace_snapshot` now enforces automatic per-project retention before and after each successful snapshot creation.
- Complete snapshots and truncated snapshots are retained separately: two complete rollback points are protected; a truncated snapshot never displaces those fallbacks and only the newest truncated diagnostic generation is retained.
- Retention groups snapshots by normalized `sourceRoot`, so simultaneous work in unrelated repositories cannot evict another project's two rollback points merely because one project produces snapshots more frequently.
- Only valid snapshot manifests participate in automatic deletion. Invalid/unreadable snapshot directories are preserved for explicit review rather than being deleted heuristically.
- The 1 GiB aggregate quota remains a final guard, but it is evaluated against the projected steady-state size after the successfully-created snapshot would replace its oldest retained generation. This allows a bounded transient write without deleting a valid fallback before the replacement is verified.
- `workspace_snapshot` returns bounded retention metrics, including removed count/bytes and steady-state projection; `workspace_snapshot_list` reports the active retention policy alongside current storage metrics.
- No generic cache, Git history, project files, `.mssr` authorities, or backups outside `data/workspace-snapshots` are part of this cleanup policy.
