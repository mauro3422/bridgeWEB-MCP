## Changes

- Added read-only `storage_growth_scan` with `auto`, `baseline`, and `status` modes.
- The tool stores a bounded size/mtime snapshot outside tracked source under `data/storage-growth/`, skips links/reparse points, and reports largest files, hot directory prefixes, new/growing/shrinking files, and coarse categories such as dependencies, build output, caches/temp, test evidence, context/memory, images, assets/media, and games/mods.
- After a complete baseline, a recursive filesystem watcher records dirty relative paths. An `auto` scan with continuous watcher coverage re-reads only those changed paths/subtrees; an unchanged pass does not recurse into the tree.
- Watcher overflow, watcher failure, Bridge restart, incomplete baselines, or any other loss of continuous coverage fail safe to a full reconciliation rather than treating a stale snapshot as authoritative.
- Added a Windows-native baseline enumerator and bounded top-level partitioning for faster first scans. Very large roots such as all of `D:\Dev` remain intentionally expensive; routine monitoring should use meaningful roots such as temp/QA artifacts, model/session stores, individual project artifact roots, or game/cache roots rather than assuming one whole-drive scan is cheap.
- Added focused regression coverage for baseline persistence, exact size growth, new files, watcher-driven incremental refresh, correct mtime conversion, and a no-change pass with zero directory rescans. The global tool-count contract is now 175.
- Added `scripts/run-storage-growth-scan.mjs` as a local diagnostic helper and `test:storage-growth` as the focused regression entry point; the storage regression is also part of the raw regression chain.
- Extended the storage report with advisory `safe-regenerable`, `review`, `preserve`, and `project-data` dispositions. Known protected datasets/runtime stores stay preserve-by-default; `.mssr/runtime`, build output, and cache/temp can be surfaced as regenerable candidates, but the policy explicitly forbids automatic deletion and still requires ownership/activity verification.
- Added the zero-dependency local **Storage Auditor** UI (`scripts/storage-auditor-app.mjs`, launcher `storage-auditor.cmd`). It reuses the exact Bridge scanner, exposes separate `D:\\Dev` / `D:\\` scopes, status/auto/baseline controls, free-space context, growth/hotspot/category tables, and a bounded Windows process-executable check so active candidate roots are visible before any cleanup decision. `test:storage-auditor` verifies the local HTTP surface plus baseline-to-incremental behavior in an isolated sandbox.
- Adopted exact packaged MSSR `0.2.75` from `vendor/mauroprime-mssr-0.2.75.tgz` (780,931 bytes; SHA-256 `3d7ea50a795b3eaf1ade3fe00be0f497c7891e46608e0d2efb6e7e1fafe1fec9`). Source dependency, lockfile and installed `node_modules` resolve to the same package.
- MSSR `0.2.75` fixes the long-lived Context Message receipt boundary where `0.2.74` could persist `selectedCount=255` and then fail every subsequent route/bootstrap while attempting the invalid `255 -> 256` transition. The fault was reproduced against the live Bridge control plane. Recovery acknowledged only the exact already-delivered `incident:docs-incidents.md` receipt through the recursion-exempt `mssr_context_ack` surface; the inbox was not edited manually.
- Added a Bridge-side installed-package regression for `selectedCount 255 -> 256` plus safe `Number.MAX_SAFE_INTEGER` saturation so future host package adoption cannot silently reintroduce the boundary mismatch.
- Adopted exact packaged MSSR `0.2.77` from `vendor/mauroprime-mssr-0.2.77.tgz` (788,977 bytes; SHA-256 `32f2fd9d86db8a9479efe4fad89eb7a812d13ac76ebf238834c1eff8df191317`). Source tarball, Bridge vendor tarball, lockfile, installed package version, and critical installed runtime files (`package.json`, `dist/trace-identity.js`, `dist/route-envelope.js`, `dist/index.js`) have exact byte parity. Runtime route/bootstrap schemas now expose `taskKey`, `parentTraceId`, and `supersedesTraceId`; lineage is correlation-only and does not mutate trace lifecycle.
- Reconciled the release verifier's `tools:list sanity` contract with the intentional 2026-09-23 removal of `blender_store_reference_image`: `scripts/verify-all.ps1` now requires canonical `image_asset_import_files`, preserves `image_asset_save` only as compatibility fallback, and no longer treats the deleted Blender Base64 helper as mandatory.
- Hardened stale ChatGPT connector catalogs as a control-plane contract rather than an image-only workaround: MCP initialize now advertises `tools.listChanged=true` and each fresh Bridge session emits `notifications/tools/list_changed` after initialization so capable hosts can re-request tool schemas; `bridge_tool_action` keeps a stable top-level `files` field annotated with `openai/fileParams` and now delegates authorized files generically to any action tool that explicitly declares the same file parameter metadata, while rejecting undeclared targets. Runtime catalog hashing now includes tool descriptions and `_meta`, so schema-adjacent contract changes such as file-parameter annotations change catalog identity. `bridge_connector_catalog_compare` derives file-aware fallback guidance from runtime metadata instead of hardcoding `image_asset_import_files`. A Bridge restart is still required to adopt new server bytes, but it is not itself proof that an already-open ChatGPT host refreshed its cached connector schema; if the host ignores the standard list-changed notification, preserve the original source files and reconnect/reopen the connector rather than regenerating or converting them to Base64. The Blender reference guide continues to treat standalone `blender-mcp reference_setup` only as the path-backed implementation primitive of the same axis-aligned installation contract.
- Human Cockpit trace cards now prefer bounded `intent.summary`, derive deterministic human-readable fallbacks when a caller omitted one, and expose task/workflow-member/technical-intermediate roles so setup traces and skill-load orphans no longer masquerade as unfinished user work.
- Dashboard aggregation now reuses one isolated read-only analytics child and persists a bounded last-good snapshot seed. Restarts can return stale dashboard evidence immediately while a cold refresh runs in the background, keeping analytics import/I/O cost off readiness and first paint; `cache.buildMs`, `cache.stale`, and `cache.refreshing` remain visible for audit.
- Human Cockpit now adds a rolling seven-day cross-project reconstruction over preserved MSSR `scope=all` history. The projection groups substantive work by observed project, excludes known synthetic/test workflows from substantive counts and human summaries, and joins at most twelve Project Health repositories to bounded local Git evidence: working-tree pressure, commits in-window, configured remotes, upstream and local tracking divergence. Dashboard refresh never fetches remotes and never scans all `D:\Dev`, so ahead/behind remains local tracking evidence rather than fresh remote truth.
- Human Cockpit now adds an **Al volver** resume projection with three explicit lanes: yesterday's work, current human work, and **Deuda MSSR**. MSSR weekly history emits host-local daily buckets plus substantive open traces; a trace is marked `needsClosureReview` only when a closure reminder follows its latest material lifecycle event and no later outcome resolves it, so work that resumes after an idle reminder is not mislabeled as abandoned. Missing outcomes no longer masquerade as active product work: those items remain auditable and resumable in lifecycle debt, with a review-first next gate and no auto-close. MSSR `0.2.77` supplies explicit stable `taskKey` plus optional correlation-only `parentTraceId` / `supersedesTraceId`; Cockpit prefers that identity and keeps project + workflow + trace only as a labeled legacy fallback. Both current work and lifecycle debt retain privacy-safe `resumePacket` provenance without storing raw prompts/transcripts/private reasoning.
- Context-layer P1/P2/P3/P4A/P5A is live: forensic/recovery workflows (`recent-work-recovery-*`, `cross-project-recovery-*`, dated recovery helpers) stay separate from the human backlog; **Qué puede hacer el sistema hoy** derives capability families from runtime tools + Skill Health + workflow-guide counts; the derived context inventory persists bounded daily/weekly resume snapshots; MSSR 0.2.77 task identity prevents future retries/agents/resumes from becoming independent human tasks when the caller supplies the same `taskKey`; and **En qué está cada proyecto** conservatively classifies observed workspace pressure without inferring finished/abandoned states. Workspace-level `D:\Dev\AGENTS.md` carries only transversal discovery/lifecycle/shared-tree rules. P6 is also complete locally: the former shared dirty tree was reconstructed on an ownership-safe recovery branch and reconciled into ten local commits through `f0deaa9`; `main` is clean and ahead of `origin/main`, with no remote push.
- Context-layer P5B adds explicit terminal project-owner evidence without creating another authority: `.mssr/PROJECT_STATE.md#Workspace status` may declare only `finished` or `abandoned-or-replaced` with required `Updated-At` plus optional bounded `Reason` / `Replaced-By`. Project Health exposes only those metadata fields, invalid declarations raise `workspace-status-invalid` / REVIEW, and Human Cockpit reopens a stale terminal declaration as `review-needed` when newer substantive MSSR work exists. Focused tests cover valid finished/replaced state, invalid metadata and stale-owner conflicts. The central `PROJECT_CONTEXT` architecture core was also narrowed from budget pressure into stable ownership bullets while detailed Context Director semantics remain in indexed knowledge/docs. Controlled HTTP restart `7920eaff-0bbe-4fc3-81f9-18c5699dc4db` adopted P5B; live health stayed ready, dashboard markup exposes terminal-state counters, and a forced fresh Project Health snapshot confirmed `workspaceStatus` metadata for 40 observed projects without mass-writing any terminal classification.
- Context Director now layers ephemeral Bridge terminal liveness over durable MSSR task/debt evidence at dashboard response time: a trace with a live recently progressing terminal is projected as runtime-active with an inspect/wait gate, while canonical closure debt is merely deferred from the visible lane and never rewritten or persisted. Lifecycle-debt cards consume bounded resume packets instead of raw trace identity as primary UI. The same bounded daily context inventory now feeds **Últimos 30 días** with truthful per-day coverage, project active-day counts, last-seen dates and retained summaries; sparse retained endpoints cannot claim a complete month and routine 30-day UI does not issue another `scope=all` historical scan.
