## Changes

- Adopts exact vendored MSSR `0.2.54` from `vendor/mauroprime-mssr-0.2.54.tgz` (615637 bytes; SHA-256 `2d91e9911430e058d19e6e51270362bcf0e02d13ee61c5bc2d1aad8c859479d7`).
- A completed `skill_bootstrap` or `skill_context_next` page now exposes `lifecycleGate` with the preserved trace/stage, an explicit phase-checkpoint template and closure instruction. Both `automaticCheckpoint` and `automaticOutcome` are always false: delivery proves neither use nor task success.
- Adds read-only `mssr_context_proposal_review` over the packaged portable contract. Fresh evidence can be `review-ready`; stale/unknown evidence requires refresh; conflicting/unavailable evidence blocks. Every result remains advisory and `autoWriteAllowed=false`.
- Server instructions bind Web callers to the complete-context → real phase work → checkpoint/replan/close sequence and make proposal review distinct from write authorization.
- Compact bootstrap responses keep selected project/context-message content but replace repeated per-candidate decision arrays with aggregate reason counts. This reserves usable page space instead of failing with a synthetic 256-character budget before skill pagination starts.
- Workflow guides above 6,000 serialized characters no longer compete with required skill units inside the compact bootstrap envelope. Bootstrap preserves the selected guide and returns an exact `workflow_guide_load` as `lifecycleGate.postContextAction`; the guide must load after the context chain and before dependent phase work.
- The standalone HTTP smoke now waits boundedly for `/readyz` before asserting the live contract. A build/watchdog replacement can transiently refuse connections; readiness is a precondition, not a reason to classify the release as failed.
