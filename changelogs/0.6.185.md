## Changes

- Add `bambu_mcp_reconnect`, which starts and validates a replacement Bambu stdio session before swapping it in, preserves the healthy old session on failure, coalesces concurrent refreshes, and drains old calls before closing that provider transport.
- Require the exact confirmation `RECONNECT_BAMBU_PROVIDER`; keep the provider path fixed/allowlisted and do not expose arbitrary commands or paths. An unchanged source is an idempotent no-op unless `force=true` is explicitly supplied.
- Report provider version, connection time, session generation, source/catalog SHA-256 fingerprints, added/removed tool names, refresh outcome, and drain result. Reconnect does not restart Bridge HTTP, the tunnel, Bambu Studio, AMS or a printer.
- Accept `application/octet-stream` only as a generic declaration after inspecting and validating actual image bytes. Preserve rejection of explicit MIME contradictions and unresolved host file IDs; show an actionable wrapper error for the latter.
- Correct the stale Bridge code-root/main/remote handoff and record which earlier Bridge handoffs remain unresolved or await runtime activation.
