# Visual Concept to Game Asset

## Purpose

Convert visual references into reproducible game assets through an evidence-first loop: inspect the actual images, extract visible characteristics, translate them into a measurable construction recipe, build a canonical prototype, capture equivalent views, compare render against reference, and iterate by the largest verified visual error.

## Non-negotiable visual loop

A prompt, caption, filename, hash or geometric metadata is not enough to claim resemblance. For every reference-driven asset, the workflow must:

1. preserve the exact prompt and original reference image;
2. inspect the reference image itself;
3. record visible characteristics and uncertainties;
4. translate those observations into geometry, materials, VFX and growth rules;
5. capture the real model from equivalent views;
6. verify that the subject is actually visible and framed in every capture;
7. inspect reference, render, overlay and contours together;
8. record preserved, missing, added and distorted characteristics;
9. change the canonical source and repeat the same comparison.

Never describe an asset as matching, improved or complete from metadata alone.

## Workflow

1. **define-visual-contract** — Define gameplay function, scale, technical constraints, required views and visual acceptance criteria.
2. **generate-divergent-concepts** — Generate meaningfully different visual families before polishing one silhouette.
3. **normalize-reference-set** — Preserve originals, choose master views and create an image-observation record.
4. **extract-geometry-recipe** — Convert observed characteristics into measurable masses, proportions, topology, materials, VFX and growth rules.
5. **choose-production-path** — Choose Roblox direct, Blender or hybrid based on the observed geometry.
6. **build-parametric-prototype** — Build a reproducible canonical source from the recipe.
7. **align-and-compare** — Capture equivalent views, prove subject presence, and compare the actual images.
8. **iterate-largest-error** — Correct the largest verified mismatch, or change family when the base direction is wrong.
9. **publish-provenance-dashboard** — Persist prompts, references, observations, recipe, source, captures, overlays, critique and decisions.
10. **maintain-pipeline** — Turn repeated visual failures into transversal validation and automation.

## Evidence rules

- Distinguish observed facts from hypotheses about hidden geometry.
- A reference-free benchmark may evaluate internal quality, but it cannot claim concept fidelity.
- A capture is invalid when the subject is absent, too small to judge, cropped unintentionally, off-center beyond tolerance, or contaminated by unrelated review assets/UI.
- Automated silhouette metrics are diagnostic only. The agent must inspect the actual paired images.
- Two iterations that do not improve the selected characteristics trigger a family or production-path review.

## Verification

- Record the last completed phase.
- Verify every persisted file and external side effect through a tool result.
- Do not publish a dashboard version as complete without valid subject-presence checks and written comparison data.
- On failure, report the exact resumable state and next action.

## Maintenance

Update `guide.json`, phase documents and schemas when the visual observation contract, validation gates or recommended tools change.
