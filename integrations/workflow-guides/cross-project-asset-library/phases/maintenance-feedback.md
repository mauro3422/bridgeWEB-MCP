# maintenance-feedback

## Goal

Feed repeated operational friction back into the correct owner without bloating the library workflow.

## Instructions

Record recurring provider-schema mismatches, drift semantics, ownership handoff failures, approval-gate confusion or recommendation misroutes as bounded maintenance evidence. Update an existing transversal skill/routing fixture only when the behavior is reusable across projects. Keep project-specific paths/statuses in project docs and avoid creating duplicate skills.
